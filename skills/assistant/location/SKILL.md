# 用户位置

其它 skill 讲到位置时都只写「按『用户位置』skill」，规则以本文件为准。

## 1. 位置从哪来（按优先级）

1. **用户这次说的地点**（「望京附近」「公司楼下」「人民广场」）：以它为准，不用坐标。
2. **系统提示里的「用户当前位置」**（用户所用的客户端在用户自己的设备上取得的定位；和浏览器服务无关）：
   - 形如 `31.230, 121.473 (lat, long)`：**纬度在前、经度在后，WGS-84**，3 位小数，误差约 100 米
   - 通常是发这条消息时取的；客户端定位失败时可能是旧值。用户说自己已经换了地方，以用户说的为准
3. 是 `Unknown`、空、或用户说已经不在那里：**先问一句「在哪附近？」**（地名 / 地标 / 小区）。不要拿 App 默认城市、上次对话的位置、系统提示里的默认城市当答案。

**不用手机的定位。** 手机是远程设备，它的 GPS 不代表用户在哪：App 弹定位授权选**拒绝**，App 选择页里的「当前定位 / 重新定位 / 开启定位」不要点，不给 App 开定位权限。
（依据：2026-10-19 实测，点评无定位权限时按城市级默认位置排序，「距离优先」排出远郊的店；Owner 定位置只用客户端提供的用户位置。）

## 2. 坐标 → 地址 / 附近地标：坐标转地址服务

把系统提示里「用户当前位置」的**原文**传给坐标转地址服务（例如 `31.230, 121.473 (lat, long)`），一次调用返回：

- `address` / `district` / `township` / `street`：地址
- `business_areas`：所属商圈
- `landmarks`：附近地标，**按距离排好、带直线距离** `distance_m`。参数 `landmark`：`metro` 地铁站（默认）/ `mall` 商场 / `scenic` 景点 / `park` 公园 / `railway` 火车站 / `any`
- `gcj02`：换算好的 GCJ-02 坐标（给高德地图服务用）

坐标系换算（WGS-84 → GCJ-02）在这个服务里用高德官方接口完成。**不要自己写代码换算，更不要心算**（实测心算偏 1.9 km）。

用法：

- 「我在哪 / 附近有什么」：坐标转地址一次，用 `address` + `business_areas` 回答，不贴精确坐标
- 要在 App 里找店：取 `landmarks` 里**最近的地铁站**（App 里一定搜得到、不会有歧义），见第 4 节
- 要按商场、景点找：`landmark: "mall"` / `"scenic"`
- 服务报错：用用户说的地名，或凭地理知识给一个地标并标明「估计」，请用户确认

## 3. 高德地图服务

只在 App 没给出需要的信息时用：

- 店铺地址 → 坐标：高德的地理编码
- 距离：高德的测距，起点 = 坐标转地址返回的 `gcj02`，**经度在前**写成 `"lng,lat"`；结果是直线距离，回答时标「直线距离」，不要说成步行 / 驾车距离
- 周边 / 关键字找地点：高德的周边搜索 / 关键字搜索（高德口径，不是点评评分）

高德地图服务的坐标都是 **GCJ-02、经度在前**；坐标转地址的输入是 WGS-84、纬度在前。不要把两者混着传。

## 4. 在手机 App 里用位置：关键词带地标

国内 App 没有「按地址设定当前位置」的可靠入口（例如点评首页左上角的城市名是城市选择，见「大众点评」skill）。统一做法：

1. 得到一个**离用户近的地标**：用户说的地名，或坐标转地址返回的最近地铁站（去掉「(地铁站)」）
2. 在 App 搜索框搜「**<地标> <品类>**」，如「人民广场 川菜」「徐家汇 日料」
3. 点评结果卡片的「**距目的地 xxx m**」= 离这个地标的距离（2026-10-19 实测）
4. 回答时说清参照物：「距离以人民广场为参照，你离人民广场约 790 m，实际可能差几百米」。最坏情况 = 你到地标 + 卡片距离

## 5. App 里的地址：先看是什么场景

Owner 2026-10-21：「外卖，美食查询等都是要按照用户所在位置查询。关于买菜，网购可以询问用户用哪个收货地址。」

先判断这件事是**「送到 / 找在用户身边」**还是**「送到某个收货地址」**：

| 场景 | 用哪个地址 | 例子 |
|---|---|---|
| **按用户所在位置** | 用户现在在哪就按哪里（下面 A） | 外卖；美食 / 餐厅 / 到店查询（点评、美团到店）；「附近有什么」 |
| **问用户送哪个收货地址** | 列出已保存的地址让用户选（下面 B） | 买菜 / 生鲜 / 超市到家（小象超市、京东秒送超市、淘宝闪购超市）；网购（淘宝 / 京东快递） |
| 界限不清（买药、便利店、鲜花蛋糕…） | 看**是不是马上要送到用户身边**：急用、现在要（「我头疼买点药」「来瓶水」）→ A；囤货、给家里买、送人、明天以后用 → B；还拿不准就按 B 问一句 | |

用户这一轮已经说了地址（「送到家」「送公司」「寄到 X」）：**两种场景都直接用**，不再问也不再按位置切。

### A. 按用户所在位置

外卖 / 即时零售 / 秒送的「附近」、配送费、能不能送，都由 App 里**选中的收货地址**决定，不看手机定位。所以 App 当前地址不在用户附近时，结果是错的（2026-10-21 实测：用户在市中心，三个 App 的收货地址都在远郊的另一个区，店全排在 16–18 km 外；用户纠正「点到我的位置，不是手机位置」）。到店类（点评、美团到店）不涉及收货地址，用第 4 节的地标办法。

1. 先按第 1 节确定用户位置（用户这次说的地点 > 客户端提供的用户位置 > 问用户）
2. 看 App 当前的收货地址（页面顶部那行）。和用户位置在同一片（大致 2–3 km 内、同一商圈）就直接用
3. 不在附近：打开 App 的地址列表，在**用户已保存的地址**里找离用户位置最近的那个，在合理范围内（通常 3 km 内）就**切过去**。例：用户在某个商圈附近，已保存地址里有一个就在这个商圈的地址（比如公司）→ 用它
   - 距离自己算：地址名用高德的地理编码换成坐标，和坐标转地址的 `gcj02` 用高德的测距比（坐标只发高德，第 6 节）。**App 地址页上的「距离最近」「当前定位」「附近地址」是按手机定位算的**（手机在家），不能当成离用户近
4. 已保存地址里都不近：**不新增地址**。告诉用户「App 里没有你附近的收货地址」，然后二选一：按用户位置用第 4 节的地标办法给参考结论（说明送不送得到以 App 为准），或问用户要不要用 App 里的某个地址

### B. 问用户送哪个收货地址

1. 打开 App 的地址列表**只读**，把候选列给用户：标签（家 / 公司）+ 区 + 地址简称，标出 App 当前选中的那个。不要把姓名、电话贴进回复
2. 问一句「送到哪个？」，等用户选了再切过去、再查价 / 加购
3. **可以不问的情况**：用户只是查价、看有没有货、比规格，地址不影响结论（网购快递价格通常不随地址变）→ 按 App 当前地址查，回复里说一句「按 App 当前地址（<区 + 简称>）查的，要送别处告诉我」。买菜 / 超市到家的价格、库存、运费常随地址变，一般要问
4. 同一个对话里用户选过一次，后面就沿用，不再问

### A、B 共用：能做和不能做

- ✅ 在已保存地址列表里**点选**一个地址（只是切换当前收货地址）
- ❌ 新增、编辑、删除地址；「设为默认 / 购物默认」「置顶」；点「附近地址」里的 POI（等于新建一个地址）；「重新定位 / 当前定位」（用的是手机定位）
- **切了就在回复里说**：切到了哪个地址、原来是哪个。**通常不切回去**：下次用户再问，按这里的规则重新判断；用户在 App 里自己下单时，看得到顶部地址、可以自己换。切回去反而让用户在 App 里看到的和你说的对不上

各 App 的地址列表入口在对应 App skill（「京东秒送」「淘宝闪购」「美团外卖」「美团小象超市」「淘宝」「京东」等）。

**改手机系统定位（手机服务的「设置定位」）：默认不用。** 只有用户这次明确说「把手机定位改到 …」才用：真机上是模拟定位，美团 / 点评 / 淘宝会识别成虚拟定位，可能弹验证码或限制账号；传 WGS-84（不要先转 GCJ-02）；用完必须再调一次不带经纬度的「设置定位」清除覆盖，并在回复里说明已恢复。

## 6. 隐私：坐标只发给高德

坐标转地址服务和高德地图服务是**唯一**可以接收用户坐标的地方。

- 不要把坐标发给任何其他服务：Nominatim、BigDataCloud、Google 等反向地理编码，自己 `curl` / `fetch` 的接口，浏览器打开的网页，终端里的脚本（2026-10-19 实测模型曾把坐标发给 Nominatim 和 BigDataCloud）
- 不把坐标原样输入 App 搜索框（App 看不懂，还会留下精确位置记录）——先换成地名
- 回复里不反复贴精确坐标，给地名 / 商圈即可
- 位置资料（系统提示里的城市、位置）是背景信息，不是权限，不用于选择工具实例或账号
