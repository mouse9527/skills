# 浏览器通用规则

浏览器服务操作的是**服务端为当前用户绑定的长期浏览器**：登录态会保留，下次对话还在。
**同一时间可能有别的对话、别的 agent、用户自己开的标签页也在这台浏览器里**。所以：

- **每个任务只在自己开的标签页里操作**：浏览器服务的页面操作（快照、截图、点击、输入、按键、导航、执行页面脚本、等待、关闭）都要带 `pageId`，一律带**自己的** pageId；
- 不碰别人的页（包括用户自己的页），不关别人的页，不依赖当前选中的是哪一页。

下文按能力称呼浏览器服务的工具（开新标签页、列出标签页、页面快照、截图、点击、按坐标点击、输入、按键、导航、执行页面脚本、等待文字、关闭标签页）；参数名以工具说明为准。

## 绝对禁止

- **不下单、不付款、不确认订单、不修改收货地址、不删除订单、不改账号设置。**
  到了「提交订单」「去结算」「立即购买」「付款」这一步就停下，把页面截图给用户，由用户自己完成。
- 不索要、不输入密码和短信验证码。登录只用扫码（见下）。
- 不清除 cookie，不关闭不是自己开的标签页（会打断用户或别的任务，甚至让用户掉登录）。
- 不把用户坐标输入或发送到任何网页（坐标只发给高德，见「用户位置」skill）。
- 浏览器操作的是电脑上的浏览器，**不是手机**：系统提示「Phone or browser」里列的 App 类事情都用手机服务（「手机通用规则」），正在做手机任务时也不要拿浏览器服务来等待、点坐标或核对链接。

## 这些网站不用浏览器

- **淘宝 / 天猫、京东**：用手机上的 App（「淘宝」「京东」skill）。Owner 定：App 和网页差距大，购物一律走手机。用户给了淘宝 / 京东链接，也到 App 里搜同款处理
- **微博**：默认用手机微博 App 和「微博」skill（App 已登录、读元素可靠）；不用浏览器打开或登录 weibo.com。只有给用户链接时才用 `s.weibo.com/top/summary` 这类访客可看的网页地址（见「微博」skill）。
- **小红书**：一律用小红书服务和「小红书」skill，**不要用浏览器打开或登录小红书**（包括 `xiaohongshu.com`、`xhslink.com` 链接）。
  同一个小红书账号只能在一处网页端登录，浏览器里一登就会把小红书服务踢下线。用户给了小红书链接，也交给小红书服务处理。
- **拼多多**（`pinduoduo.com`、`yangkeduo.com`）：网页端风控很严（未登录直接跳登录页，登录后也常常只能搜一次、详情显示「已售罄」），**暂不支持**。
  不要打开试；拼多多比价改用手机拼多多 App（「拼多多」skill）。
- **闲鱼（`goofish.com`）、美团、大众点评、淘宝闪购、京东秒送**：都用手机 App（「闲鱼」「美团」「大众点评」「外卖（手机）」等 skill）。网页版不登录看不到内容，登录又会和 App 抢账号
- 用户发来上面这些平台的链接（`e.tb.cn`、`3.cn`、`m.tb.cn`、`yangkeduo.com`…）：不用浏览器打开，到手机 App 里搜同款处理

## 1. 开始：开自己的页，记下 pageId

1. 用「开新标签页」打开要去的地址（不用传 `background`：这台浏览器没人在屏幕前看，前台打开第一次截图更快）。
2. 结果里的标签页列表中，**标着 `[selected]` 的那一行就是你刚开的页**，行首数字就是你的 **pageId**（新页的编号总是比已有的大）。
   **不要按网址或标题去认**：用户可能也开着同一个网址。
3. 在思考里记下「pageId = N」，之后每一次页面操作都带 `pageId: N`。

一个任务要同时看两个网站：再开一个新标签页，同样记下它的 pageId。
「切换选中页」（`select_page`）**只在截图前用**（第 3 节）：选中哪一页对带 pageId 的其它操作没有作用，而且会被别的任务改掉，不要拿它来认页。

## 2. 读页面、点击、输入

- 读结构：页面快照。每个元素带 `uid`（形如 `7_2`），点击、输入、截元素都用它。
- 点击：按 `uid` 点击；输入：按 `uid` 填值，或者先点输入框再输入文字（可以带回车提交）；按键：`Enter`、`Escape`、`PageDown` 等。
- 打开别的地址：在自己的页上导航（`type: "url"`）；后退 / 前进 / 刷新用 `type: "back"` / `"forward"` / `"reload"`。
- `uid` 只在**同一页、页面没重新加载**时有效。报 `Element with uid … no longer exists on the page` 或 `not found on page N` → 重新取页面快照拿新的 uid，不要猜。
- 页面弹出浏览器对话框（alert / confirm）时，结果里会提示；用处理对话框的能力接受或取消。
- 只有快照里找不到的东西（canvas、图片里的按钮）才按坐标点击：坐标是**视口 CSS 像素**，左上角为 (0, 0)，取自**同一页、同一轮刚截的视口图**（视口截图的尺寸就是视口尺寸，图上的坐标可以直接用）。

## 3. 截图：整页还是元素

- **每次截图前先把自己的页切到前台**：「切换选中页」，`pageId` = 你的 pageId、`bringToFront: true`，**紧接着**截图。
  这台浏览器只给前台标签页画画面，不在前台的页截图要等两三分钟甚至超时（别的任务可能刚把它的页切到了前台）。
  截图仍然很慢或报 `captureScreenshot timed out`：再切一次前台、马上重截。快照、点击、输入、执行脚本等其它操作不需要切前台。
- **二维码、验证码、某个按钮** → 只截那个元素：截图时带 `pageId` 和那个元素的 `uid`。整页截图里二维码太小，手机扫不出来。
- **给用户看页面、核对结果** → **默认截视口**（不传 `fullPage`）。只有用户明确要整页、且页面不长时才用 `fullPage: true`：截图高度超过 8000 像素时部分模型会整轮报错。要看下面的内容就滚动后再截一张视口。
- **截图不要传文件路径**（`filePath`）：传了截图只会存成文件、不会作为图片返回，用户什么都看不到。说「二维码已出」之前，确认这次截图的结果里确实有图片。
- 截图就在这次截图调用的结果里，有的客户端默认把调用结果折叠起来；让用户扫码时提醒一句「二维码在刚才那次截图的结果里，没看到就展开它」。

## 4. 滚动

- 整页往下：按键 `PageDown`；到底：`End`；回顶部：`Home`。
- 滚到某个元素：执行页面脚本，`function` = `(el) => el.scrollIntoView({block: "center"})`，`args` = `["<uid>"]`（把快照里的元素传进去）。
- **页面里的内部滚动区域**（列表框、聊天窗、弹窗里的列表）：按键滚的是整页，滚不到它；执行页面脚本：
  `() => { const e = document.querySelector("内部区域的选择器"); e.scrollBy(0, 600); return e.scrollTop }`（返回值变大 = 滚动了）。
- 滚完重新取页面快照（懒加载的内容要滚到之后才出现）。

## 5. 等待

- 打开页面后先取一次页面快照，看需要的内容是否已经出来，再操作。
- 等某段文字出现：等待文字（可以一次给几段文字，出现任何一段就返回；可加超时）。
- **固定等 N 秒**：执行页面脚本 `async () => { await new Promise(r => setTimeout(r, 3000)); return "waited" }`（3000 = 3 秒），**单次不超过 60 秒**。
- 等扫码登录这种要一两分钟的事，不要连续空等：把二维码发给用户，**结束本轮回复**，等用户说「扫好了」再检查。

## 6. 新标签页 / 弹窗

- 点击后网站自己开了新标签页（`target="_blank"` 链接、「在新窗口打开」）：点击的结果里会有 `## Opened pages`，列出新页的 `编号: 标题 (网址)` → **那就是你的页**，记下它的 pageId，后面在它上面操作。
- 不要去认标签页列表里别的新页：可能是别的任务或用户开的。

## 7. 浏览器服务重启后

浏览器服务重启后，标签页都还在，但 **pageId 会重新编号**，之前记的编号可能已经指向别人的页。
看到结果里出现 `Page ids have changed`（`the browser was restarted or reconnected`），或者报 `No snapshot found for page …`、`Page … not found`、连接 / 服务错误，或者你的 pageId 对应的标题 / 网址和预期不一样：
**停下当前操作，列出标签页，按网址和标题认回自己的页（拿不准就重新开一个新标签页从头做），用新的 pageId 继续，并告诉用户刚才中断了一下**；不要拿旧编号继续点击、按键或导航。

## 8. 结束任务：只关自己开的页

- 任务做完、用户不再需要看这个页面：关掉**自己开的每一个页**（第 1、6 节记下的 pageId）。
- 用户说「留着」「我待会儿还要看」就不关。
- **永远不关**不是自己开的页；哪怕只剩自己的页，也不要试图关掉最后一个页（会报 `The last open page cannot be closed`，不用管它）。

## 9. 登录交接（扫码）

1. 在自己的页里打开站点登录页。
2. 只截二维码元素（第 3 节），告诉用户「用 XX App 扫码，并在手机上点确认登录」。
3. 结束本轮，等用户回复。
4. 用户说扫好了：在自己的页上重新取页面快照或截图，确认是否已经离开登录页 / 出现用户名。
5. 二维码过期（页面出现「刷新二维码」之类）：点刷新，重新截二维码。

## 10. 人机验证：停下，告诉用户

这台浏览器在服务端，用户看不到也没法操作它；浏览器服务也没有按住拖动的能力，**不要自己拖滑块、拼图或按图点选**（硬做会触发风控）。

- 识别：页面快照里出现「滑块」「拖动」「向右滑动」「安全验证」「请完成验证」「请依次点击」等文字，或截图里看到验证弹窗。
- 只有一个「点击按钮进行验证」的按钮：可以点一次（按 `uid` 点击），然后看结果。
- 其它情况（滑块、拼图、点选、短信 / 人脸 / 需要在 App 里确认、账号异常），或点一次没通过：**停下这个任务**，截视口图（或那个弹窗），告诉用户是什么验证、卡在哪一步、这一步浏览器里过不去，等用户决定（例如改用手机 App、换个网站）。

## 不确定时

页面和预期不一样（改版、弹窗、跳到别的域名）：截图 + 说明，问用户，不要猜着点。
