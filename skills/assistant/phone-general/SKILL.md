# 手机通用规则

手机服务操作的是**服务端为当前用户绑定的那部真手机**，App 里登录的是**用户本人的主账号**。不要根据称呼、服务名或对话内容去猜、切换或尝试别的设备 / 账号。
手机是否在用户身边、能不能收短信，以系统提示里的「设备事实」为准；没写就当不知道，不要猜（默认手机不在用户身边，用户碰不到）。
每一个点击都是真的：会进购物车、会留下浏览记录、会触发风控。只做用户要求的事。

本文件是所有手机 App skill 的公共部分；App skill 只写该 App 特有的方向、参考界面和坑。

**一口气做完再回复**：读完 skill 就直接开始操作手机，中间**不要发「我先看一下…」「接下来我去…」之类的进度消息就结束这一轮**——回复一发出，这一轮就结束了，手机操作也停了（2026-10-20 实测：Sonnet 三次在说完「下一步要做什么」后就停下，用户只能追问「怎么又停下了」）。要说的话放进最后的结果里。**只有这些情况才停下来回复**：任务做完了；需要用户决定（选哪个、要不要加购）；要用户本人操作（登录、短信、付款、验证 3 次失败）；遇到硬规则禁止的步骤。
**硬规则**（Owner 定，不能变通）：不提交订单 / 不付款；手机任务不用浏览器服务；同一验证最多 3 次，短信 / 人脸 / 账号风险 / 登录交人；美团系不用 deep link；不用手机定位、坐标只发高德；拼多多只读比价（不拼单、不下单、不领券）。其余都是建议：按当前界面判断，界面和 skill 写的不一样时以界面为准。

## 1. 什么时候用手机

- **用手机的**：淘宝 / 京东网购（Owner 定：App 比网页好用，不用浏览器）、闲鱼二手、微博（热搜 / 话题 / 博主，只读）、外卖与即时零售（美团外卖、美团小象超市、淘宝闪购、京东秒送）、大众点评 / 美团到店的店铺、团购、评价。
- 不用手机的：小红书（小红书服务）；一般资料查询、看官网（联网搜索 / 浏览器）。
- **拼多多只读比价**（Owner 2026-10-21 放开）：看价格、和淘宝 / 京东比价可以，用「拼多多」skill；不拼单、不下单、不领券、不先用后付、不助力分享。拼多多网页端仍不用（见「浏览器通用规则」）。
- **一次只做一个任务**，做完一件再做下一件；不要在两个 App 之间来回切。
- 需要用户位置时，先按「用户位置」skill 处理。

## 2. 手机任务只用手机服务

浏览器服务控制的是另一台电脑上的浏览器（见系统提示「Phone or browser」），手机任务从头到尾只用手机服务的能力。手机服务没有专门的等待能力：页面在加载就再读一次元素 / 再截一次图。

下文的「读元素」「截图」专指这两个工具（同一服务里要分清）：

- **读元素** = `mobile_list_elements_on_screen`：列出屏幕上的元素，带 `@ref`、文字、坐标
- **截图** = `mobile_take_screenshot`：截一张图给自己看 / 给用户看

| 要做的事 | 用手机服务的这类能力 |
|---|---|
| 看屏幕上有什么 | 读元素（需要看图时截图） |
| 点（ref 或坐标） | 点击屏幕（传 `ref`，或传截图换算后的 `x` / `y`） |
| 等页面加载 | 再读一次元素 / 再截一次图 |
| 输入文字 | 输入文字 |
| 滚动 / 滑动 | 滑动屏幕 |
| 返回 / 回车 / 删除 | 按键（`BACK` / `ENTER` / `DEL`） |

## 3. 绝对禁止

- **不提交订单、不付款、不确认支付、不点「立即购买」「立即抢购」「去支付」「提交订单」。** 到了这一步**就停**：截图给用户，说明「已备好，请在手机上自己确认提交并付款」。
- 进了结算页之后**不许用批量执行**（一次执行一串动作的那个能力），一次只点一下，每下之前先看清楚要点的是什么。
- 不新增 / 编辑 / 删除收货地址、不「设为默认」；**在已保存地址里切换当前收货地址是允许的**，按「用户位置」skill 第 5 节（让外卖等的地址对齐用户位置）。不删除 / 取消订单、不改账号 / 隐私 / 支付设置、不开通会员或免密、不点「领」红包 / 淘金币 / 会员券之类的按钮（除非用户要求）。
- 不点广告、不点「领红包去下载」「打开 XX App」之类的跳转（除非用户要求）。
- 不发评价、不发私信、不联系商家 / 骑手（除非用户明确要求，且先把要发的内容给用户确认）。
- **分享面板只点「复制链接」**（购物 App 取商品链接时用，做法和禁点清单见「购物通用」的「给用户商品链接」）：联系人、微信 / QQ / 朋友圈 / 支付宝 / 钉钉 / 微博等渠道、生成海报 / 保存图片、「分享领红包」都不点——点联系人就是直接发给真人。面板里**按坐标点**（见第 4 节「ref 会漂移」），点前截图核对，点完读剪贴板确认。
- **默认不用打开链接（deep link）的能力**：美团系实测会触发风控验证码。只有某个 App skill 明确写了「已验证可用」的链接才用。**任何时候都不许打开支付 / 拨号类链接**：`alipays://`、`alipay://`、`weixin://`、`wxpay`、`tel:`、`sms:`、`intent:`。
- 不装、不卸 App，不改系统设置（除非用户明确要求；装 App 只从系统应用商店装）。
- 不用手机定位、不改手机系统定位、定位授权弹窗选拒绝（详见「用户位置」skill）。

## 4. 怎么看界面：先读元素，再点

- **通常先读元素**，按返回的 `@ref` 点。元素里有文字、按钮、输入框里的当前内容，很多卡片的 `label` 已经把「标题 + 价格 + 销量 / 评分」拼在一起，直接读它最准；价格被拆成一位一个的小节点时，读父节点的 `label`
- **截图用在这些时候**：元素里找不到要点的东西；要看图片里的内容（商品图、菜品图里的字、验证码）；要给用户看结果；元素和预期明显对不上，或返回的几乎只有状态栏 / 底栏
- 参考 2026-10-20 实测：京东首页 / 搜索 / 结果 / 商品页 / 秒送、淘宝首页 / 搜索 / 结果 / 商品页、美团首页 / 搜索结果 / 外卖店铺页、点评都能读到；**读不到的**：京东和淘宝的购物车、淘宝闪购的店铺列表、美团小象超市（小程序）——这些页面直接截图
- 按截图点时，用截图结果里附带的坐标换算说明换成屏幕坐标，再点击屏幕传 `x` / `y`；估坐标容易点错 tab、点到浮窗，能用 ref 就用 ref
- **ref 会漂移**：`@ref` 是「读元素时第几个节点」，点击时会**重新读一次界面再按编号找**。页面上有倒计时、轮播、刷新中的信息流，或者状态栏网速 / 通知图标变了，编号会整体偏几位，点到旁边的东西（参考 2026-10-22：拼多多同一静止详情页 10 秒内「分享」按钮编号在 @e156 / @e164 / @e172 之间跳；分享面板里按 ref 点「复制链接」点成了「分享图片」）。所以**旁边挨着危险项的按钮不按 ref 点，按坐标点**：用刚读到的元素的 `at=x,y size=w×h` 算中心 `(x + w/2, y + h/2)`，或截图换算。典型：分享面板（旁边是联系人 / 微信）、拼多多「分享到拼小圈 | 分享」、底栏购买按钮旁边的按钮。普通的 tab、搜索框、商品卡用 ref 没问题，点完看结果对不对
- 例子（参考 2026-10-20）：淘宝搜索结果页读一次元素就能拿到每件商品「标题 价格 付款人数」，比价时**不用每屏截图**；只有要看商品图、或元素里没有的东西才截图（实测某次会话截图 16 次、读元素 3 次，大部分截图都可以省）

### 手机可能正被另一个对话用着

同一部手机可能有另一个对话（或用户本人）同时在操作，手机服务本身发现不了。所以每次读到界面时，和**自己上一步离开时**对一下：

| 读到的 | 多半是 | 怎么办 |
|---|---|---|
| 弹窗、广告、红包、开屏页、「已进入防误触模式」，关掉后还是原来那个 App 和页面 | App 自己弹的 | 关掉继续 |
| 自己点了之后 App 跳到了别的页 / 别的 App（例如点商品打开了小程序、点「去使用」跳到领券页） | 自己这一步引起的 | BACK 回来继续 |
| 熄屏 / 全黑 | 第 5 节 | 唤醒 |
| **任务刚开始**，打开 App 落在以前留下的页面（别的店、旧搜索词、上次的结果页） | 热启动回到上次停留的页面，正常 | 不算占用，回首页或直接从这里开始 |
| **前台换成了一个自己没打开过的 App**（自己按 BACK / HOME 也不会跳进一个从没打开过的 App）；页面不是自己打开过的（例如另一家店、另一个搜索词的结果）；输入框里有不是自己输入的文字；购物车 / 地址变了 | **可能另一个对话在用手机** | **停下**，不要继续点，也不要把 App 切回来抢手机。回复用户「手机好像正被另一个对话（或你本人）在用：我上一步在 X，现在前台变成了 Y。等那边用完再叫我」 |

拿不准时宁可停下问一句：抢着操作会把两个对话的任务都弄乱。**不要用启动 App 的能力把自己的 App 切回来「试一下」**——对面如果还在用，这一下就是在抢（参考 2026-10-21 实测：一个模型察觉了，却切回去试，结果继续做完了任务）。

## 5. 熄屏怎么办

手机**经常是熄屏的**（屏幕不常亮，Owner 定）。

**截图全黑 / 元素只剩状态栏时，先分清是哪种**（通常查一次前台 App 就能分）：

| 现象 | 多半是 | 怎么办 |
|---|---|---|
| 查前台 App 报错，读元素也报错 | 熄屏 | 按下面的唤醒步骤 |
| 查前台 App 正常（App 在前台），刚点完或刚切页 | **页面在跳转 / 加载**（参考 2026-10-20：点开淘宝购物车商品后就这样，再截一次就正常） | 再读一次元素或再截一次，不用唤醒 |
| 唤醒后、等加载后还是全黑，且在登录 / 支付 / 订单类页面 | 安全页面（`FLAG_SECURE`） | 交给用户（第 7 节） |

唤醒步骤（参考 2026-10-20 实测）：

1. **按一次 POWER 键**点亮屏幕（手机服务没有 WAKEUP 键）。然后读一次元素
2. 如果读元素还是报「No UI hierarchy… screen is most likely off or locked」，或屏幕上是「已进入防误触模式」：这是小米的**防误触**挡着，**VOLUME_UP 和 VOLUME_DOWN 都按一次**（它自己提示的退出方式；两个都按，音量才不会变），再读一次元素——实测这样就恢复了
3. 如果停在锁屏：能上滑解锁就从屏幕下部往上滑一下；需要密码 / 生物识别就停下告诉用户，不要尝试
4. 做完这几步截图**还是全黑**，才当作安全页面处理（见第 7 节「交给用户」）

POWER 是开关：亮着的时候再按会熄掉。按之前不确定亮不亮，可以先查一次前台 App——熄屏时它会报错，亮着时会返回前台 App。不要反复按 POWER。

## 6. 输入文字

参考 2026-10-20 实测：手机的输入法（讯飞，中文模式）会把**纯英文 / 数字**的输入当拼音组字（「airpods pro 3」进框变成「a3日颇大PRO」「3AirPodsPRO」，「airpodspro3」只剩「3」）；**只要文字里有一个中文字，就会原样进去**（「苹果AirPods Pro 3」「苹果降噪耳机第三代」都一字不差）。

- 点输入框；框里有旧内容先清空（找「×」/「清空搜索框中内容」之类；注意别点成「清除历史记录」——那是删搜索历史）。不清空的话新文字会接在后面
- 关键词**尽量带上中文**（「苹果AirPods Pro 3」比「airpods pro 3」可靠）
- 输入之后**读一次元素，看输入框里的字对不对**（输入框的 `text` / `value` 就是当前内容）
- 不对：清空重输一次；还不对就点联想词 / 历史搜索里合适的那条。同一个关键词别反复试超过两轮
- **输入后框还是空的**（中文是靠剪贴板粘贴进去的，个别 App 的输入框不接，参考 2026-10-21 闲鱼搜索框）：点开键盘工具栏 / 右下角的**剪贴板**面板，点刚才那条文字插入，再读元素核对。剪贴板面板只用来插入，不删条目、不改输入法设置
- **提交后核对搜索真的生效了**：读一次元素看结果页顶部的关键词是不是这次输入的、输入框里有没有残留旧词。还要看**是不是在店内搜索**：从店铺页进去的搜索框只搜这一家店（参考 2026-10-20：进了某旗舰店后连续多次都在店内搜，结果页出现「没有找到更多商品，为您推荐本店其他商品」才发现）——要全站搜索，先 BACK 回首页或结果页，再用顶部搜索框
- 批量执行里**不能放截图**（会报错）；要在批量执行里看结果，用它的「结束时读元素」选项（`listElementsAtEnd`）
- 不要用 `mobile_save_screenshot` 把截图存到手机里（存到哪都不给用户看）；给用户看用截图

## 7. 验证码：自己完成

用户通常不在手机旁边，**弹验证就自己做完**，做不完再交给用户。

**先认出来**：打开 App 或换页后，先看是不是验证页（标题「验证」「安全验证」，或元素里有「请依次点击」「拖动滑块」「向右滑动」）。美团系**冷启动也可能直接弹**（2026-10-20 实测：打开美团 App 第一屏就是验证，不是只有 deep link 才弹）。

### 点选（「请依次点击下图图标 / 文字」，美团系最常见）
1. 截图看清：上方的**目标顺序**和下方大图里每个目标的位置
2. 截图是缩小过的：**按截图结果里附带的坐标换算说明**换成屏幕坐标（不要直接用截图像素）。点每个目标的**中心**
3. 按顺序逐个点击屏幕，**每点之间停 0.5–1 秒**（不要批量执行一口气点完——太快像机器）
4. 有「确定 / 提交」就点它；再截图看结果
5. 失败（提示错误 / 换了新图）：**先等 3–5 秒**，重新截图、按新图重做；图看不清点右下角刷新（↻）

### 滑块
- **拼图缺口**：截图找滑块起点和缺口位置，换算成屏幕坐标，从滑块中心出发向右滑（`direction: right`、`distance` = 缺口 x − 滑块 x）
- **按说明松手**（美团 2026-10-20 实测见到：「拖动滑块，刚露出完整的 1 个钥匙就松开」）：先截图读懂说明和图，估出松手位置再一次滑过去；这种没有实测成功率，失败按重试规则处理
- **拖到最右**：起点滑块中心，终点滑道右端往里一点
- 拖完截图看结果。滑块对轨迹敏感，成功率比点选低，属正常
- 实测（2026-10-20，大众点评）：一次任务里连续弹了拼图滑块 ×2、向右滑动 ×1、点选图标 ×1，按上面的方法各 1 次就通过

### 重试上限（保护账号）
- **同一个验证最多 3 次**（含刷新换图）。3 次都失败：停手，截图告诉用户「XX App 的验证我没能通过，需要你方便时在手机上点一下」，**本次对话不再碰这个 App**
- 验证通过后放慢：少翻页、不重复搜同一个词。在回复里说一句「刚才过了一个验证」

### 交给用户、不要自己做的
- **唤醒之后截图仍是全黑**：Android 安全页面（`FLAG_SECURE`，登录 / 支付 / 部分订单页）。不要盲点，告诉用户（熄屏的处理见第 5 节，先唤醒）
- **短信验证码**：不要点「获取验证码」。设备事实说这部手机收不到短信（例如没有 SIM 卡）时，告诉用户这个 App 要短信验证，需要用户在自己的手机上处理；没写就问用户
- **人脸识别、「账号存在风险」「设备异常」「请在常用设备登录」「账号已被限制」**：立即停，截图交给用户，不做任何别的操作
- App 掉登录：告诉用户需要登录，由用户自己登录，不要尝试密码登录

## 8. 怎么做得快

每次工具调用都要等模型想一遍（几秒），**少调一次就快几秒**（实测耗时 85–90% 在模型这边，手机每步约 1–1.5 秒）。不限调用次数，但不做多余的调用。

1. **开头只列一次设备**拿 device id，后面一直用它。列表里没有设备就停下告诉用户，不要试别的 device id。
2. 启动 App（包名见 App skill）后**先看是不是验证页 / 弹窗**，再点首页搜索框搜；不要逛频道，搜到后用**筛选 / 排序**，不要一屏屏滚、不要换很多关键词重搜。
3. **看界面**按第 4 节：先读元素、按 ref 点；截图只在需要时用（截图比读元素慢，也更容易点偏）。
4. **一串已知的动作用批量执行**（例如：点搜索框 → 输入 → 回车，加 `listElementsAtEnd: true` 看结果）。结算页之后不许批量执行。
5. 不要每点一下都截图确认，只在关键节点看：进了店、加完购物车、到了结算页。
6. **弹窗直接关**：开屏广告、红包 / 淘金币 / 外卖券弹层、「开启通知」「去评分」「新版本 · 立即升级」——点「跳过」「关闭」「×」「暂不」「以后再说」，**不点「领」「开心收下」「立即领取」「开通」「立即升级」**。
7. 页面切换后元素没变化：等一下再读一次（App 在加载）；还是没进展就换个办法（截图、BACK、换入口），不要原地反复点同一个地方。

## 9. 结束时

- 说清停在哪一页、看到 / 备好了什么（店名、菜名 × 数量、价格、配送费、预计送达），附关键页截图。
- 收起弹出的**筛选面板、键盘、浮层**（`BACK`），不要留在屏幕上。
- 不要退出 App、不要清空购物车、不要关后台。
- 中途放弃的任务：退回到 App 首页（按 `BACK` 几次），不要留在半填的表单上。
